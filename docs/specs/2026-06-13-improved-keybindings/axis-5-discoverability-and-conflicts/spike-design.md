**Unknown.** Reframed so the load-bearing half is primary. TWO sub-questions, weighted. (PRIMARY — truthfulness, needs the build): walked over the FULL production binding set (initialize_app population, app crate), do the three competing conflict definitions yield N_exact_eq <= N_overlap < N_naive, and CRUCIALLY: is the N_naive->N_overlap reduction a substantive class or a single-artifact cosmetic win, and how many cross-view collisions REMAIN conflicts under (c) because the engine has no identifier-exclusion model? (SECONDARY — soundness, needs a small self-contained build, ZERO keymap data): can a sound+complete can_both_be_true over the 7 variants be implemented by atom-enumeration with map-key exclusivity, no external SAT crate, no unsafe, agreeing with a brute-force oracle on >=100k randomized pairs incl. same-key/different-value and absent/sentinel cases? **Hypothesis.** Soundness: YES, atom-enumeration with map-key exclusivity is sound/complete and SAT-free; NotEqual(k,v) is provably Not(Equal(k,v)) (context.rs:109-114, unwrap_or(true)) so the Not-of-Equal modeling is correct; the single 3-valued key collapses to {One,None,other-or-absent} (Many and absent are indistinguishable given only One/None are referenced). Cost: YES trivially — but for the CORRECTED reason (predicates are id-dominated + one 3-valued key, not "map-atoms absent"), so the 20-guard never fires on real data. Truthfulness: the SHARP caveat is now the headline, not a footnote. The Vim forks are explicit-contradiction pairs (& id!("Vim") vs & !id!("Vim"), actions.rs:54-104), so the expected N_naive->N_overlap reduction is NEGATION-driven (Vim/FLAG/IMEOpen contradictions), NOT cross-view disjointness. Cross-view collisions (the conflicts users actually hit rebinding over a fixed key in another pane) REMAIN conflicts under (c) because no exclusion model exists. So the most likely real outcome is: N_overlap < N_naive but the win is a thin negation-artifact class, and the genuine truthful-conflicts deliverable requires a NEW identifier-exclusion-group primitive that (c) alone does not provide. There is a real chance N_exact_eq == N_overlap (no same-key overlapping-but-unequal pair exists), in which case ship the trivial (a).

_Why code can't settle it:_ Partially recanted vs the original. The SOUNDNESS half cannot be settled by reading (only differential testing against a brute-force oracle proves the no-SAT enumeration isn't an independent-boolean shortcut that happens to look right) — a genuine build. **The spike:** Throwaway can_both_be_true(&ContextPredicate,&ContextPredicate)->bool by atom-enumeration (no SAT crate, no unsafe), reusing ContextPredicate::eval (context.rs:101-119) as the per-assignment oracle. Union the atoms across both predicates: id-atoms as independent booleans; map-key atoms grouped per key, each key taking ONE referenced value or an 'other/absent' sentinel (models exclusivity AND the NotEqual=Not(Equal) absent-true asymmetry). Enumerate assignments, build synthetic Context, true if both eval true for any. >20-atom guard -> conservative true + overflow counter (a SAFETY GUARD, not a measured finding: it cannot fire on real data). Then walk the REAL keymap, bucket bindings by resolved single Keystroke, emit N_naive/N_exact_eq/N_overlap AND a removal-cause breakdown AND a count of cross-view collisions that REMAIN conflicts under (c).
