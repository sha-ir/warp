## Axis 2 — Scope & context control

### A2-Q4 — DESCOPED · time-box: hours

**Unknown.** Given the flagship forks are pure-Identifier Fixed bindings and the editable same-name-fork population does not yet exist, the ONLY genuinely runtime-uncertain sub-question is: can a brute-force eval-implication checker be made bit-identical to `ContextPredicate::eval` over the AWKWARD production predicate shapes — specifically same-key multi-value `Equal`/`Or` (terminal block-selection, init.rs:459-460) where atoms are NOT independent booleans (a key cannot be both "One" and "None"), plus the asymmetric absent-key defaults (`Equal`→false/fail-closed, `NotEqual`→true/fail-open at context.rs:104-113) — at a tractable enumeration budget? The Exact-vs-natural and drift-stability sub-questions are NOT runtime unknowns: they are settled by `#[derive(PartialEq)]` + non-commutative `And` + the absence of any `FromStr` (Exact unusable from natural input), and by the per-run `AtomicUsize` BindingId + the definition of hashing mutable input (hash/id not drift-stable). So the headline "{0,1,>=2} histogram + orphan rate over a realistic population" is the wrong unknown; the real unknown is narrow subsumption fidelity, and even it is only on the critical path if A2-Q5 picks mutate AND a Fixed->Editable migration actually creates divergent editable forks.

**Hypothesis.** The original conclusion (targeting must be by an author-assigned stable id; zero=warn+no-op, multi=never-silent-apply-to-all) is correct, but it is reachable mostly on PAPER, not via the proposed population build. Two corrections: (1) Exact and hash/BindingId are disqualified by code already read (derive-PartialEq + non-commutative And + no parser; AtomicUsize + hash-of-mutable-input), so no histogram/orphan harness is needed to reject them. (2) The design fixates on the WRONG subsumption subtlety: `Equal`/`NotEqual` absent-key fail-open is vacuous for the modeled pure-Identifier population (2^k-over-atoms is exactly faithful there, so the disagreement counter is structurally 0 = false green); the REAL soundness trap is same-key multi-value mutual exclusion (`Cardinality` can't be One and None at once), which ONLY the terminal predicates (init.rs:459-460) exhibit and which the synthetic Vim fixtures omit. Net: author-assigned stable id is the safe recommendation, made conditional on A2-Q5 picking mutate; subsumption is implementable-but-fragile and should be rejected for shipping unless proven bit-identical to eval on the same-key-multi-value shape with an explicit "undecidable/too-large ⇒ refuse, never silently mis-target" guard.

_Why code can't settle it:_ Only ONE narrow thing resists code-reading: whether a per-key value-domain `implies()` can be made bit-identical to `ContextPredicate::eval` (context.rs:101-119) over the same-key multi-value `Equal`/`Or` production shape (init.rs:459-460) at a tractable budget — because there atoms are not independent (a naive truth table over atoms admits the impossible world "key=One AND key=None"), and `Equal`/`NotEqual` carry asymmetric absent-key defaults; the disagreement only surfaces by running both side by side on that shape. Everything else the original `why_code_cant_settle` listed is in fact code-settleable and was settled here: Exact's structural brittleness from `#[derive(PartialEq)]` (context.rs:9) plus non-commutative `And`, the absence of any `FromStr`/`Display`, BindingId's non-persistability from the per-run `AtomicUsize` (keymap.rs:264-272), and hash drift from the definition of hashing a mutable predicate. The "{0,1,>=2} histogram over a realistic population" cannot be settled NOT because it is a deep runtime property but because the population is synthetic/nonexistent (A2-Q5-D migration unbuilt) — which makes any number it produces untrustworthy, not decisive.

**The spike:** Replace the 1-2 day synthetic-population spike with: (A) a half-day paper decision-memo that records the three relations' properties from code already read, and (B) one ~2-hour throwaway unit test that probes ONLY the genuinely-uncertain thing — whether a per-key value-domain eval-implication checker is bit-identical to ContextPredicate::eval on the AWKWARD production shapes. Drop the {0,1,>=2} histogram, the orphan harness (tautology), canonical_id (belongs to A2-Q6/A2-Q15), and update_custom_trigger_scoped (belongs to A2-Q5). The memo states: Exact = derive-PartialEq structural + non-commutative And + no FromStr ⇒ unusable from natural input + leaks internal spelling; BindingId = per-run AtomicUsize ⇒ not persistable; name+pred-hash ⇒ drifts by definition ⇒ targeting key must be an author-assigned stable id, UNLESS A2-Q5 picks inject (matcher.rs:262 already selects by precedence ⇒ no relation needed).

- _Touch points:_ `crates/warpui_core/src/keymap/context.rs: add throwaway `fn implies(a:&ContextPredicate,b:&ContextPredicate)->Option<bool>` that enumerates over PER-KEY VALUE-DOMAINS (each key = absent | one of the finite values mentioned for that key; each Identifier = present|absent), NOT 2^k over independent atoms; returns None if the domain product exceeds a small budget (refuse, don't guess)`, `crates/warpui_core/src/keymap/context_tests.rs: ONE #[cfg(test)] fn asserting implies()-consistency-with-eval (disagreement count must be 0) over a fixture set that PROVABLY includes (i) the pure-Identifier Vim-fork shape `text_entry & id!("Vim")` vs `& !id!("Vim")` AND (ii) the same-key multi-value terminal shape `eq!(k,"One") | eq!(k,"None")` from app/src/terminal/view/init.rs:459-460 AND (iii) an absent-key `NotEqual` case — the test MUST fail if implies() is built as a 2^k-over-atoms enumerator`, `NO production touch_points in THIS spike: do not build update_custom_trigger_scoped or canonical_id; if A2-Q5=mutate and editable forks exist, fold the same-name-fork assertion into the A2-Q17 harness rather than standing up a parallel one`

- ✅ **Success:** Conditional and conjunction-gated, not a standalone green: (1) The fidelity test's disagreement counter is 0 over a fixture set that PROVABLY contains >=1 same-key multi-value `Equal`/`Or` predicate (init.rs:459-460 shape) AND >=1 absent-key `NotEqual` case — proving a per-key-domain implies() CAN be made sound, i.e. subsumption is at least faithfully implementable; if the same test is re-run with a 2^k-over-atoms enumerator it MUST report a non-zero disagreement (demonstrating the trap is real and caught). (2) Paper side: Exact is shown uninstantiable-from-natural-input (`And` non-commutative + no `FromStr`) and hash/BindingId shown non-persistable/drift ⇒ the schema override key (A2-Q3) must be an author-assigned stable id field. (3) The recommendation is decisive ONLY in conjunction with A2-Q5 selecting mutate; if A2-Q5 selects inject, the success signal is "A2-Q4 is moot — dispatch eval (matcher.rs:262) selects by precedence, no relation needed."
- 🛑 **Kill:** Stop/pivot if ANY: (1) A2-Q5 picks the INJECT path — the existing dispatch-time `context_predicate.eval(ctx)` (matcher.rs:262) already selects the right binding by precedence, so no target-relation is needed and A2-Q4 collapses to "store {name,trigger,predicate} as a new higher-precedence binding"; (2) A2-Q13/A3 confirms there are no editable same-name forks AND the Fixed->Editable migration (A2-Q5-D) is not being built this phase — targeting has no population to act on (today the flagship forks are Fixed and EditableBindings default to `Just(true)`, keymap.rs:657); (3) the fidelity test shows a sound per-key-domain implies() cannot be kept within budget on the terminal shapes (or any future same-key Equal with a large value domain) — subsumption is unshippable, author-assigned id is forced, and no further build is warranted. Also: if the natural-predicate ergonomics question is raised, it is un-answerable until A2-Q6/A2-Q15 ship a `FromStr`/canonical form — do not fabricate a parser inside this spike to "measure" ergonomics.
- ⚠️ **False-green risk:** The original 1-2 day spike's GREEN is untrustworthy three concrete ways: (1) FIDELITY MIRAGE — it models pure-Identifier Vim forks, where every atom is an independent boolean, so the `implies()`-vs-`eval` disagreement counter is structurally 0 and falsely certifies subsumption fidelity; meanwhile production's terminal predicates `eq!(k,\"One\") | eq!(k,\"None\")` (init.rs:459-460) violate any 2^k-over-atoms enumeration (the key cannot be two values at once), so a subsumption primitive validated on the synthetic set is silently unsound on the real one. The fidelity test MUST enumerate per-key value-domains AND MUST include that same-key multi-value shape, and MUST show a 2^k enumerator failing it, or its green is fake. (2) TAUTOLOGY-AS-MEASUREMENT — the "orphan rate" is definitionally 100% for any override targeting an edited fork (hash of mutable input), so a low synthetic number masks nothing; reporting it as empirical manufactures false confidence. The fix (author-assigned stable handle, never a derived hash, never BindingId) must be mandated by reasoning regardless of any number. (3) PHANTOM POPULATION — the histogram runs on forks that do not exist (A2-Q5-D migration unbuilt), with guessed predicate spellings and a non-existent natural-predicate parser, so any "relation X is exactly-1" is provisional on artifacts that do not exist, and is moot entirely if A2-Q5 picks inject. Additionally the design's "Equal/NotEqual fail OPEN" framing is half-wrong (Equal fails CLOSED to false; only NotEqual fails open), and its `override⊆binding` subsumption-direction notation contradicts its own `text_entry`-over-matches example — both must be pinned or the success criterion is untestable.
